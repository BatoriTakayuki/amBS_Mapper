# amBS Mapper

Nanoporeで読んだ**アンプリコンバイサルファイトシーケンス**を、マウスゲノム（GRCm39）に対応づけて、**タグ（サンプル）別・アレル（母/父）別**にCpGメチル化を判定し、QUMA-san形式の「写真」と集計表を出力するツールです。Mouse_Strain_Checkerと同じく、`start.bat`のダブルクリックで起動し、ブラウザで操作します。

**研究用プロトタイプ v0.5.0（2026-10-27）。** Nanopore（FASTQ / 未アライメントBAM）のみ対応しています。シミュレーションリード、QUMAとの突き合わせ、実データで確認しています（後述）。

タグは「インライン（プライマー直前の配列）」と「Nextera デュアルインデックス（i5/i7）」の2形式に対応します。タグやプライマーが分からないときは、**リード構造の調査**でFASTQだけから候補を調べられます。

## 起動

1. Docker Desktopを起動できる状態にしておきます。
2. このフォルダの **`start.bat` をダブルクリック**します。初回はビルドに数分かかります。
3. ブラウザで **http://localhost:8503** が開きます（Mouse_Strain_Checkerは8502なので同時に使えます）。

停止は `docker compose stop`、次回は `start.bat` で再開します。

### 参照ゲノム

初回は画面の「参照ゲノムを準備」で次の2つを用意します（どちらも1回だけ）。

1. GRCm39（Ensembl release 113、約800 MB、展開後2.7 GB）のダウンロード。Mouse_Strain_Checkerの `data/resources/reference.fa` と `.fai` があれば、`data/resources/` にコピー（同じドライブならハードリンク）するだけで使えます。
2. **バイサルファイト用のゲノム索引**（minimap2、k=19、約13 GB）。32スレッド機で約4分、作成時のメモリ約20 GB。Dockerのボリューム（`index`）に保存します。Windowsのフォルダに置くと読み込みに約3分かかりますが、ボリュームなら約17秒です。ボリュームを消すと（`docker compose down -v`）作り直しになります。

解析時はメモリを約15 GB使います（索引はプロセス間で共有）。

系統SNPは Mouse Genomes Project REL-2112 v8（GRCm39）を**アンプリコン領域だけ**インターネット経由で取得し、`data/resources/variant_cache` に保存します。23 GBのVCF全体をダウンロードする必要はありません。

### インターネットから取得するもの

解析そのものはDockerの中で完結しますが、次のものは外部から取得します（リードなどのデータは外部に送信しません）。

| いつ | 取得するもの | 取得元 |
|---|---|---|
| 初回ビルド | Pythonパッケージ（`requirements.txt`）、samtools・bcftools など | PyPI、Debian |
| 参照ゲノムの準備（1回だけ） | GRCm39 FASTA（Ensembl release 113） | ftp.ensembl.org |
| 系統一覧・新しいアンプリコンの確認時 | MGP REL-2112 v8 のSNP/indel（領域だけ、tabix経由） | ftp.ebi.ac.uk |

一度取得したSNPは `data/resources/variant_cache` に保存され、同じアンプリコン・系統なら再取得しません。VCFを手元に置く場合は、環境変数 `AMBS_SNP_VCF`・`AMBS_INDEL_VCF` にパス（索引付きの .vcf.gz）を指定できます。画面のIGV（igv.js）は同梱しているので、表示にインターネットは不要です。

## 使い方

1. **入力ファイル**: FASTQ（`.fastq` `.fq` `.gz`）または未アライメントBAMを `data\input\` に置き、「更新」して選択します。フォルダを選ぶと中のファイルをすべて使います（Macが作る `._` で始まるファイルは無視します）。
   - **リード構造を調べる**: 選んだファイルだけから、Nexteraアダプターの有無、i5×i7の組み合わせごとのリード数、アンプリコン候補（インサート両端から推定したプライマー、バイサルファイト変換の有無、GRCm39上の位置、完全長リードの割合、候補ごとのインデックスの組み合わせ）を調べます。結果のボタンで、候補をアンプリコン表に、インデックスの組み合わせをサンプル表に取り込めます。結果は `explore.xlsx` にも保存します。
2. **アンプリコン**: 次のどちらかで指定します。
   - **プライマー**: バイサルファイト用のForward/Reverseプライマー（タグなし、5'→3'、Y/R等のIUPAC表記可）と最大産物長。ゲノム上の位置はバイサルファイト変換ゲノム上のin-silico PCRで探します（初回は約30～50秒、2回目からはキャッシュ）。F/Rを逆に入れた場合は入れ替えて解析し、注意を表示します。完全一致のみ探すので、プライマーにミスマッチがある場合は領域で指定してください。
   - **領域**: `chr12:109494123-109494444` のようなGRCm39の座標と鎖（+: 上鎖のCpGを見る、-: 下鎖）。プライマー検索をしません。ロングリードや位置が分かっている場合に使います（最大200 kb）。プライマーも入力すればタグの位置合わせとプライマー内CpGの除外に使い、なければ領域の両端を目印にします。
3. **サンプル**: まず**タグ形式**を選び、1行1サンプルで、タグ、母系統、父系統を入力します。
   - インライン: タグF（Forwardプライマーの5'側）、タグR（Reverseプライマーの5'側）。
   - Nextera: i5・i7をNextera XTの名前（`S520` `N712`）か、サンプルシートと同じ向きの8塩基で入力します。インデックスとプライマーの間のNexteraアダプター（33/34塩基）と、外側のP5/P7末端を確認して判定します。i5/i7がどちらのプライマー側にあっても構いません。
   - **サンプル表を空にして「自動サンプル」の母系統・父系統だけ入れると**、Nextera形式ではインデックスの組み合わせごと、インライン形式ではアンプリコンごとに自動でサンプルを作ります（合格リードが「自動サンプルにする最少合格リード数」未満の組み合わせは除外）。
   - 系統は `B6` `JF1` のような略称、`JF1_MsJ` のようなMGP名、一意に決まる前方一致（`CAST`→`CAST_EiJ`）で入力できます。
   - 正逆交配（B6×JF1とJF1×B6）は行ごとに母父を入れれば混在できます。母と父が同じ系統ならアレル分けをしません。
   - タグとプライマーの間にスペーサーがある場合は、スペーサーまでタグに含めてください。タグは片側だけでも構いません。
   - 「FASTQ限定」は、ファイル（またはフォルダ）ごとにサンプルが分かれている場合だけ指定します。
   - Excelの表をコピーして「Excelから貼り付け」に貼れば一括で入力できます。
4. **「プライマーとSNPを確認」**で、産物の位置・CpG数・アレル判定に使えるSNP数を先に確認できます。
5. **「解析開始」**。ジョブは1つずつ順番に実行し、ブラウザを閉じても続きます。

入力内容はブラウザに自動保存されます。「設定を保存／読込」でJSONファイルとしても保存でき、履歴の「設定を復元」で過去の解析の入力を呼び出せます。

## 処理の順番と理由

| 順 | 処理 | 理由 |
|---|---|---|
| 1 | **ゲノム全体へのマッピング** | 全リードをGRCm39全体にマッピングし、位置と由来鎖（上鎖・下鎖とそれぞれの相補鎖）を決めます（下記）。アンプリコンに重なるリードだけを次に進め、それ以外は「アンプリコン外」として、どこに何本載ったかを集計します。ロングリードや想定外の産物にも対応するためです。 |
| 1b | **アンプリコン内の精密な整列** | アンプリコンに重なったリードを、そのアンプリコンの配列にもう一度整列し（C→T変換、minimap2 map-ont）、リードの向きとプライマーの位置を確定します。 |
| 2 | **タグ判定** | 整列で分かったプライマー位置の直前（5'側）にタグを探します。タグの3'端をプライマー（Nexteraではアダプター）に固定して編集距離で比べるため、端の余分な配列に惑わされません。最良と次点が同点なら「曖昧」として除外します。Nexteraではキットの全インデックスを候補にするので、サンプル表にないインデックスのリードが近いサンプルに紛れ込みません。 |
| 3 | **品質判定**（QUMAと同じ基準） | 被覆率、一致率、ミスマッチ率、CpH変換率、未変換CpH数で不合格のリードを除きます。 |
| 4 | **アレル判定** | 母系統と父系統で異なるSNPを使います。各SNPの前後8塩基を両方の系統配列と比べ、近い方に1票を入れます（ホモポリマー付近でのギャップ位置のずれに強くするため）。票の80%以上が一致した方のアレルに割り当て、SNPが読めない・票が割れたリードは「判定不能」とします。 |
| 5 | **CpG判定** | 整列位置の元の塩基がCならメチル化（●）、Tなら非メチル化（○）。片方の系統にだけあるCpGは、そのアレルのリードだけで判定します。 |

### ゲノム全体へのマッピングの方法

ゲノムをC→T変換した配列（上鎖用）とG→A変換した配列（下鎖用）を1つの索引にし、リードもC→TとG→Aの2通りに変換してminimap2で整列します。整列した組み合わせから、由来鎖が OT（上鎖）、CTOT（上鎖の相補鎖、PCRのコピー）、OB（下鎖）、CTOB（下鎖の相補鎖）のどれかが決まります。Bismarkと同じ考え方です。

- アンプリコンの「鎖」と由来鎖が合わないリードは「反対鎖の産物」として除外します。
- 1本のリードに2つの分子がつながっている場合（Nanoporeのライブラリ作製で起こる）は、アンプリコンに載った部分を使います。アンプリコンを2つ含むリードはキメラとして除外します。
- 3文字（A/G/T）になった配列は似た配列が増えるため、k-merを19にしています。実データ2万リードで、k=15と同じ正確さ（アンプリコンのリードの97.9%が正しい位置）で約25倍速くなりました。
- 未変換のリードもマッピングされます（C→T変換すると変換の有無に関係なく一致するため）。

**C/T型のSNP（逆鎖ではG/A）は、バイサルファイト変換と区別できないためアレル判定に使いません。** 使えるSNPがないアンプリコンでは、全リードが「判定不能」になります（確認画面で分かります）。

## 判定条件（詳細設定）

既定値は、QUMA-sanの `setting.csv` の値を基にしています。

| 設定 | 既定 | QUMAとの対応 |
|---|---|---|
| アンプリコン被覆率の下限 | 90% | なし（ロングリードで途中までのリードを許すなら下げる） |
| 一致率の下限 | 90% | `-p`（同じ意味） |
| ミスマッチ率の上限 | 10% | `-m`。**QUMAは個数、本ツールは整列長に対する割合**。Nanoporeは長さによってエラー数が変わるため割合にしています |
| CpH変換率の下限 | 90% | `-c`（同じ意味） |
| 未変換CpHの上限 | 6個 | `-u`（同じ意味）。空欄なら制限なし。長いアンプリコンでは空欄を推奨します |
| タグの許容誤差 | 2塩基 | — |
| SNP位置の塩基品質の下限 | 10 | — |
| アレル判定に必要なSNP一致率 | 80% | — |
| 自動サンプルにする最少合格リード数 | 50 | — |
| Nextera: 片側のインデックスだけのリードも使う | はい | — （下記） |
| プライマー内のCpGを除外 | はい | QUMAは入力配列全体を解析します。プライマー部分はプライマー配列そのものでメチル化を反映しないため、既定で除外しています |

### 片側のインデックスしかないリード（Nextera）

Nanoporeは、インデックスPCRで片側しか伸びなかった分子（例: `[P5][i5][A1]…[A2]` で終わり、i7とP7がない）も読みます。Illuminaではクラスターを作らないので見えない分子です。

- 読めた側のインデックスでサンプルが**1つに決まる**ときだけ、そのサンプルに割り当てます（サンプル表の「うち片側タグのみ」に数を表示）。
- 決まらないときは「タグが複数サンプルに一致」になります。
- 自動サンプルで、両側がそろったリードが1本もないアンプリコンは、片側のインデックスごとに「S520（片側のみ）」のようなサンプルにまとめます。**複数サンプルの混合の可能性があるので、解釈に注意してください。**

### 入れ子のアンプリコン

同じForwardプライマーで長い産物と短い産物を増やす設計（短い方が長い方に含まれる）では、リードが両端までそろう方のアンプリコンに割り当てます。重なる位置への複数の一致はキメラ扱いしません。

## 出力

結果画面に表示し、個別ファイルまたはZIPで保存できます（`data/results/<解析ID>/output/`）。

| ファイル | 内容 |
|---|---|
| `photos/*.png` | **写真**。サンプル×アレル（母・父・判定不能・全リード）ごとに、●メチル化 ○非メチル化 で並べた図。QUMA-sanと同じく、メチル化数の少ない順→パターン順に並べます。60リード以下は丸、それ以上は塗りつぶしの図。既定では最大200リードを無作為抽出して表示し、メチル化率は全リードから計算します。 |
| `photo.xlsx` | QUMA-sanの `photo_data.xlsx` と同じ形式（●のセルを黒塗り）。シートはサンプル×アレルごと。 |
| `summary.xlsx` | 設定、サンプル別集計（各段階のリード数、アレル別メチル化率）、CpG別メチル化率、リードの振り分け、アンプリコン外にマッピングされた領域、アンプリコン、SNP一覧。 |
| `plots/*.png` | サンプル別メチル化率の棒グラフ、CpG別メチル化率の折れ線グラフ。 |
| `cpg_methylation.csv`, `samples.csv` | 上の集計のCSV版。 |
| `reads.tsv.gz` | 全リードの判定（サンプル、タグ、状態、一致率、変換率、SNP票、アレル、メチル化パターン、ゲノム位置、由来鎖、マッピング品質）。 |
| `reads.bam`, `reads.bam.bai` | IGV用。ゲノムにマッピングできた全リード（下記）。 |

パターン記号: `M` メチル化、`U` 非メチル化、`-` 欠失・範囲外、`N` C/T以外の塩基、`.` そのアレルではCpGでない。

### 画面の中のIGV

結果画面の「IGVを表示」で、ブラウザの中にIGV（igv.js 3.0.0、同梱。インターネット不要）が開きます。

- トラックはサンプル（タグ）ごとと、アンプリコンごとの「タグ不明」。チェックボックスで表示を切り替えます（最初はタグ不明と最初の3サンプル）。アンプリコン名のボタンでその位置へ移動します。
- CpGは赤＝メチル化、青＝非メチル化（写真と同じ判定）。「CpG番号」トラックの番号は写真の列番号と同じです。
- リードの両端の色付きの塩基は、ゲノムに並ばなかった部分（タグ・アダプター・インデックスなど）で、拡大すると1塩基ずつ読めます。
- リードをクリックすると、i5/i7（読めたインデックス、または理由）、判定（YT）などが表示されます。
- igv.jsにはバイサルファイト表示がないため、表示用のBAM（`output/igv/`）ではCpGの判定を塩基修飾（MM/MLタグ）として持たせ、非メチル化CpGのT（下鎖はA）を表示上だけC（G）にしています。ダウンロード用のBAMは変更していません。v0.5.0より前の解析は、再解析すると表示できます。

### IGVでリードを見る（`bam_by_sample.zip`、`reads.bam`）

- **`bam_by_sample.zip`（おすすめ）**: サンプルごとのBAM（`サンプル名_アンプリコン名.bam`、メチル化率の計算に使った合格リードのみ）と、アンプリコンごとの `タグ不明_アンプリコン名.bam`（アンプリコンに載ったがサンプルに割り当てられなかったリード。タグが読めない `tag_unknown` と複数サンプルに一致 `tag_ambiguous`。品質判定の前に外れたので不合格のリードも含む）。展開してIGVで .bam をまとめて開くと、サンプルごとに1トラックになります。
- **`reads.bam`**: ゲノム（GRCm39、染色体名は `12` などEnsembl形式）にマッピングできた全リード。不合格やアンプリコン外のリードも見たいとき用。

1. IGVでゲノム「Mouse (GRCm39/mm39)」を選び、File → Load from File で .bam を開きます（索引 .bai を同じフォルダに置く。`12` と `chr12` はIGVが自動で対応づけます）。
2. 右クリック →「Color alignments by」→「bisulfite mode」→「CG」で、CpGのメチル化が赤、非メチル化が青になります。
3. 右クリック →「Group alignments by」で、「sample」はサンプル別、「phase」はアレル別（1: 母、2: 父）、「tag」に `YT` と入れると判定結果別に並びます。

BAMの中身:

- SEQは元のリードの塩基です。FLAGの向き（逆鎖フラグ）は**リードの向きではなく由来鎖**（上鎖: 順、下鎖: 逆）を表します。PCRのコピー鎖（CTOT/CTOB）も元の鎖として表示されるので、IGVのバイサルファイト表示が正しく色分けされ、方向性ライブラリを前提にしたツール（MethylDackelなど）でもそのまま扱えます。
- アンプリコン上のリードは、アンプリコンの外にはみ出した部分（アダプターやタグをアライナーがゲノムに無理に並べた部分）をソフトクリップしています。
- インデックス: `i5`・`i7`（Nextera）、`tf`・`tr`（インライン）に、読めたインデックス名（`S520` など）か、読めなかった理由を記録します。`no_index`＝インデックスが付いていない（Nexteraアダプターの外にP5/P7がない）、`unreadable`＝付いているが読めない、`ambiguous`＝複数に同じくらい一致、`no_adapter`＝プライマーの外にNexteraアダプターがない、`no_primer`＝リード上にプライマーが見つからない。`reads.tsv.gz` の `tag_f_label`・`tag_r_label` 列も同じです。
- タグ: `RG`（サンプル）、`HP`（1: 母アレル、2: 父アレル）、`YT`（判定結果の英語コード。pass、off_target など）、`YA`（アンプリコン）、`YB`（由来鎖 OT/CTOT/OB/CTOB）、`XR`/`XG`（Bismarkと同じ変換の向き）。
- ゲノムにマッピングできなかったリードは含みません。
- IGVは参照（B6）の配列でCpGかどうかを決めます。SNPで片方の系統にしかないCpGでは、IGVの色とツールの結果（その系統のリードだけで計算）が違って見えます。

## 検証

| 検証 | 結果 |
|---|---|
| 単体テスト（合成ゲノム、上鎖・下鎖の両方） | `docker compose run --rm --entrypoint python ambs-mapper -m pytest -q /app/tests`：18件合格（Nexteraタグ、入れ子アンプリコン、ゲノムマッピング、IGV用BAM、画面IGVの塩基修飾タグを含む） |
| 全ゲノムのin-silico PCR | GRCm39で実在の領域（chr12、420 bp）から設計したプライマーが一意の産物になることを確認（約53秒） |
| シミュレーション（実在領域、B6/JF1の実SNP4個、4サンプル×2,000リード、エラー率5%、正逆交配と同系統対照を含む） | サンプル割当の正解率 99.99%（未割当1.9%）、アレル判定の正解率 100%（判定不能4.7%）、CpG判定の正解率 97.9% |
| 同条件でエラー率10% | サンプル 99.9%、アレル 100%、CpG 96.2% |
| **QUMA（QUMA-sanのDocker環境）との突き合わせ**（同じ400リード） | CpG位置は完全一致、CpGごとの判定の一致率 99.91%、真値に対する正解率はQUMA・本ツールとも 97.98% |
| 速度 | 8,000リードを16スレッドで約1秒（QUMAは400リードで17秒） |
| ブラウザ画面からのAPI経由の解析、結果表示、ZIP保存 | 動作確認済み |
| ゲノム全体へのマッピング方式への切り替え（実データ285,773リード） | 旧方式（アンプリコンだけに整列）の合格リード26,526本のうち26,524本が同じサンプル・アレル・メチル化パターン。旧方式でキメラとされた87本を追加で使用。全体の処理時間 約36秒（32スレッド） |
| IGV用BAM（実データ） | BAMの塩基から数えたCpGごとのメチル化率が、ツールの結果と一致（上鎖・下鎖のアンプリコンで最大差1.1ポイント）。系統特異的なCpG（SNPで片方の系統にしかないCpG）は、ツールがその系統のリードだけで計算するため差が出る（想定どおり）。samtools quickcheck 合格、日本語のサンプル名も可 |

## 制限

- 現在はNanoporeのアンプリコンのみ。MiSeqのペアエンドは未対応です。
- 参照はGRCm39（mm39）のみです。mm10の座標が必要な場合は変換してください。
- アレル判定はSNPのみを使います。系統間のindelは警告を出すだけで、判定には使いません。
- UMIによる重複除去はしていません（PCR増幅の偏りはそのまま残ります）。
- リード構造の調査はNexteraライブラリ向けです。推定プライマーはインサート両端の共通配列（最長22塩基）なので、実際のプライマーが分かればそちらを使ってください。候補の位置は長いインサートをマッピングして決め、推定プライマーがゲノムに一致すればプライマー検索で端を正確に合わせます。
- 解析対象は指定したアンプリコン（領域）だけです。全ゲノムのCpGを一覧するモード（全ゲノムのロングリードBS-seq向け）はまだありません。
- 1本のリードに2つのアンプリコンが続くリードはキメラとして除外します。
- ロングリードのアンプリコン（数kb以上）は最大産物長を上げるか、領域で指定すれば扱えます。途中で切れたリードも使う場合は被覆率の下限を下げてください。
